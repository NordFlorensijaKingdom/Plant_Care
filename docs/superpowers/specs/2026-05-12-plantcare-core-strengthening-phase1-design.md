# PlantCare — Этап 1 “Усиление базового ядра”

## Контекст

Проект — мобильное приложение для ухода за растениями на React Native (Expo, expo-router). Данные растений хранятся в `AsyncStorage` через `PlantContext`.

Текущие возможности:
- Параметры ухода на уровне растения: `wateringEnabled/mistingEnabled`, интервалы, `lastWatered/lastMisted`.
- События ухода/здоровья: лог (в текущей кодовой базе он называется `logs`).
- Кастомизация цветов через `ThemeContext` и `useColors`.

## Цели этапа

1) Расширить модель растения новыми базовыми полями.
2) Обновить Add/Edit Plant, чтобы новые поля вводились и сохранялись.
3) Добавить экран “Сегодня” (Dashboard), собирающий due-задачи по всем растениям, с действиями “Выполнено” и “Перенести на 1 час”.
4) Добавить историю ухода (единый лог событий) и отображение в профиле растения.
5) Улучшить уведомления: “Пропустить” = snooze на +1 час, а также “тихие часы” (22:00–08:00) с возможностью отключения.

## Нецели этапа

- Не добавлять новые типы ухода (удобрения, обрезка и т.п.).
- Не делать кастомный календарь/datepicker: даты вводятся текстом.
- Не делать полноценные action-кнопки внутри системных push-уведомлений на этом этапе (только логика и UI в приложении).
- Не ломать текущую систему кастомизации цветов/темы.
- Не мигрировать все существующие иконки на Lucide (Lucide используется только в новом UI).

## Решения (важные соглашения)

### 1) Единая история событий

Вводится единый массив `history` для событий:
- `water`
- `mist`
- `health`

Он становится источником для UI “История” в профиле. Текущий лог `logs` будет мигрирован в `history` (по возможности), после чего в коде используется только `history`.

### 2) Snooze как данные растения

Snooze хранится на уровне растения и учитывается при вычислении “due” задач:
- `snooze.waterUntil`
- `snooze.mistUntil`

Перенос на 1 час = запись соответствующего `*Until = now + 1h` и перепланирование уведомления на это время (с учётом “тихих часов”).

### 3) “Тихие часы”

- Интервал: 22:00–08:00 (локальное время устройства).
- Настраиваемость: только включение/выключение через Settings.
- Если рассчитанный `triggerMs` попадает в “тихие часы”, он переносится на ближайшие 08:00.

## Модель данных

### Plant (добавляемые поля)

- `location: string`
- `purchaseDate: number | null` (timestamp ms)
- `lastRepotted: number | null` (timestamp ms)
- `lightLevel: 1 | 2 | 3 | 4 | 5`
- `difficulty: 1 | 2 | 3 | 4 | 5`
- `history: CareHistoryEntry[]`
- `snooze: { waterUntil: number | null; mistUntil: number | null }`

### CareHistoryEntry

- `id: string`
- `timestamp: number`
- `type: "water" | "mist" | "health"`
- `healthStatus?: HealthStatus`
- `comment?: string`

Примечание: `healthStatus/comment` используются только для `type="health"`, но структура допускает их наличие и для остальных типов в будущем.

### Хранилище

- Растения: новый ключ `plant_care_plants_v4`.
  - При старте: попытка прочитать v4 → иначе миграция из v3 (`plant_care_plants_v3`) → запись в v4.
  - В миграции добавляются defaults для новых полей.
  - Логика конвертации `logs → history`:
    - `water/mist/health` переводятся в `history` со схожими полями.
    - После миграции `logs` игнорируется.
- Настройки приложения: новый ключ `plant_care_settings_v1`:
  - `quietHoursEnabled: boolean` (default: true).

## UI/UX

### 1) Add/Edit Plant

Добавить поля ввода:
- Location: текст.
- Purchase date / Last repotted: текст `YYYY-MM-DD` с валидацией, сохраняется как timestamp (00:00 локального времени).
- Light level / Difficulty: выбор из 5 уровней через “чипы/кнопки” (1–5) с подписью (например: “Очень низкий … Очень яркий”, “Очень простой … Очень сложный”).

### 2) Tabs / Навигация

Добавить новый таб:
- `(tabs)/today.tsx` — экран “Сегодня”.

Порядок табов: Today → Garden (существующий index) → Add → Settings.

### 3) Today (Dashboard)

Экран отображает список задач по всем растениям:
- Due-задача “Полив”:
  - `wateringEnabled === true`
  - `lastWatered === null` или `now >= lastWatered + intervalMs`
  - snooze: если `snooze.waterUntil && now < snooze.waterUntil`, задача не считается due
- Due-задача “Опрыскивание” — аналогично.

Карточка задачи:
- Название растения, тип задачи, индикатор “Overdue/Now”.
- Кнопки:
  - “Выполнено” — сбрасывает таймер через `waterPlant/mistPlant` и пишет запись в историю.
  - “Перенести на 1 час” — snooze на +1 час + перепланирование уведомления на это время.

Иконки:
- Для нового UI использовать `lucide-react-native` (не трогая существующие Ionicons/Feather в старом UI).

### 4) Профиль растения: История

История отображает `history` (water/mist/health), отсортированную по `timestamp` desc:
- вода/опрыскивание: тип + время.
- здоровье: тип + бейдж статуса + комментарий.

## Уведомления

### Планирование (тихие часы)

При расчёте времени следующего уведомления:
- сначала вычислить `baseTriggerMs` (по интервалу или snooze),
- затем применить quiet hours: `adjustForQuietHours(baseTriggerMs, quietHoursEnabled)` → итоговый `triggerMs`.

### “Пропустить”

“Пропустить” трактуется как “не сейчас”:
- на уровне приложения — действие snooze +1 час для соответствующего ухода.
- на уровне уведомления — action-кнопки не внедряются в этом этапе (подключаются позже).

## Критерии приёмки

1) Новые поля `location/purchaseDate/lastRepotted/lightLevel/difficulty` доступны в Add/Edit Plant и сохраняются/восстанавливаются после перезапуска.
2) Экран Today показывает все due-задачи по всем растениям; “Выполнено” обновляет таймер и добавляет запись в историю.
3) Snooze скрывает задачу на 1 час и переносит уведомление (если оно было запланировано).
4) История в профиле показывает события ухода/здоровья в правильном порядке.
5) Quiet hours (по умолчанию включены) не допускают уведомления в 22:00–08:00 и переносят их на 08:00; настройку можно отключить в Settings.
